a nas on a raspberry pi

written 2020-04-24 · 2 min

A 500 GB laptop drive pulled out of a dead machine, a Raspberry Pi 3 that was already sitting on the desk, and a spare enclosure. Network storage you own outright, for roughly the price of the SATA cable.

The idea is unglamorous: hang the disk off a board that is always on, share it over SMB, and let every machine in the house mount it. Samba does the actual work.

filesystems first

The drive came formatted NTFS and I wanted it readable elsewhere too, so the Pi needs the drivers for the filesystems Linux does not ship with:

$ sudo apt-get install ntfs-3g
$ sudo apt-get install exfat-utils exfat-fuse
$ sudo apt-get install samba samba-common-bin

mounting the disk

Make a mount point at the root, open it up, then find where the kernel put the disk and mount it there.

$ sudo mkdir /MKS_Server
$ sudo chmod 777 /MKS_Server
$ lsblk                      # find the device — sda1, usually
$ sudo mount /dev/sda1 /MKS_Server

chmod 777 is the blunt instrument here, and it is worth being honest that this whole setup trades access control for convenience — it is a share on a LAN I control, not something to expose.

sharing it

Samba's config is one block appended to the bottom of /etc/samba/smb.conf:

$ sudo nano /etc/samba/smb.conf

[MKS_Server]
comment = home nas
path = /MKS_Server
browseable = yes
read only = no
writeable = yes
create mask = 0777
directory mask = 0777
public = no
force user = root

Samba keeps its own password database separate from the system's, which catches people out — adding a Linux user is not enough, you have to give that user an SMB password too.

$ sudo adduser user_name
$ sudo smbpasswd -a user_name
$ sudo /etc/init.d/smbd restart
$ sudo /etc/init.d/nmbd restart

surviving a reboot

This is the step that gets skipped, and then the share quietly vanishes the first time the power blips. A manual mount does not persist — it needs an fstab entry:

$ sudo nano /etc/fstab

/dev/sda1  /MKS_Server  auto  defaults,user  0  2

Mounting by /dev/sda1 works right up until a second USB disk gets plugged in and the names shuffle. blkid will give you the drive's UUID, and UUID=… /MKS_Server auto defaults,user 0 2 is the version that does not care what order things enumerate in.

The other half of surviving a reboot is being findable. A NAS on DHCP is a NAS whose address changes, so pin it in /etc/dhcpcd.conf:

static ip_address = 192.168.0.23/24
static routers = 192.168.0.1
static domain_name_servers = 192.168.0.1

Reboot, and the share comes back on its own at a fixed address — \\192.168.0.23 from Windows, smb://192.168.0.23 from a Mac.

What you end up with is a private cloud that costs nothing per month and keeps working when the internet does not. The Pi 3 saturates its 100 Mbit ethernet long before the disk breaks a sweat, which is the real ceiling here — but for backups and media that run overnight, it never mattered.
